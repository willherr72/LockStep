Eight wires between the brains

Four data wires carry the app link and both ROM bootloaders — the C6 side lands on UART0 (GPIO16/17), the same pins its ROM bootloader listens on. Four straps let each chip hard-reset the other into its bootloader: mutual unbrickability is wiring, not firmware.

One connector, three separate buses — and one deliberate NC. The USB-C receptacle fans out: D+/D− go only to the STM32 (PA11/PA12, via ESD array); CC1/CC2 go to the AP33772S — PD negotiation lives entirely on the CC wire; VBUS passes through the AP33772S's NMOS into the ideal-diode OR. The AP33772S's DP/DN pins exist only for moisture detection, and the datasheet explicitly allows leaving them unconnected when that function is waived (pins 18/19, "could be unconnected") — waived here, because the data pair is the STM32's live USB bus. The only feature traded away is connector moisture sensing.

Why FDCAN2, not FDCAN1. On the G4, BOOT0 shares PB8 — and on a 64-pin package FDCAN1 can only land on PB8/PB9 (PA11/PA12 belong to USB). CAN RX idles high, which would pull BOOT0 high at every reset and boot the ROM loader instead of the app. Using FDCAN2 on PB5/PB6 keeps PB8 as a real, C6-drivable BOOT0 with a local pull-down. Verified: the G491 has both FDCAN1 and FDCAN2 (PB5/PB6, AF9, per the ST pin database) — no fallback needed.

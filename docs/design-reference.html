Node architecture FIG.1

The smart-actuator node

Every LockStep node is identical. An ESP32-S3 runs the show; a TMC5130 with an internal ramp generator handles the motor so WiFi jitter never corrupts step timing; a magnetic encoder closes the loop.

Power tree FIG.2

Two rails, dual-sourced

USB-C PD and the harness feed a shared ~20 V rail through an ideal-diode OR — so any node can be the base, and the node's 20 V can never back-feed the PC. A wide-input buck makes 3.3 V from anywhere between 5 V (USB) and 20 V (PD).

You can't drive the motor from PC USB. 5 V sits below the TMC5130's ~6 V undervoltage lockout, so USB powers the logic only — perfect for flashing/config with the motor idle. Motor power always comes from the 20 V supply. That power-domain separation is what the design needs; an optoisolator is not.

Bus topology FIG.3

One CAN bus, terminated at the ends

Nodes daisy-chain over Micro-Fit — a linear CAN bus with power passing through. A 120 Ω terminator plug goes in each of the two unused end jacks; never in the middle.

Control transports

One command set, three ways in

USB

Native USB-Serial-JTAG for flashing; CDC virtual serial for control and config.

bench / development

CAN

The control path inside the arm — a host or master node streams joint targets over the bus.

in the machine

WiFi / BLE

Wireless control and OTA updates — built into the ESP32-S3, no extra radio.

remote

Every node is a gateway. Because each node has both USB and CAN, plugging USB into (or connecting WiFi to) any single joint reaches the whole chain — no external USB-CAN dongle required.

Ecosystem tiers

One platform, two power tiers

Same ESP32-S3 brain, same CAN protocol, same firmware. Micro-Fit is the universal signal connector across every tier — only the power path changes.

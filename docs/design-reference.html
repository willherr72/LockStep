Node architecture FIG.1

Split brain: motion is wired, wireless is a peripheral

An STM32G491 owns everything deterministic — driver, encoder, CAN-FD, USB. The ESP32-C6 lives outside the motion domain and touches it through exactly one framed UART link, so an RF-stack crash can never disturb the motor loop.

One bridge, one direction of trust. The UART link is the wireless domain's only path in. The TMC5130's internal ramp generator still owns step timing, the G4 owns the loop, and nothing the radio does — crash, reconnect, OTA — can touch either.

Power tree FIG.2

Dual-sourced VM, two-stage logic power

USB-C PD and the harness feed VM through an ideal-diode OR — any node can be the base, and node power never back-feeds the PC. One 60 V-rated buck makes 5 V for the FD transceiver on both tiers; 3V3 cascades off it through a second buck.

The arm knows its power budget. The AP33772S negotiates autonomously at boot; the STM32 then reads the granted PDO over I2C and sets motor current from the real wattage — a 65 W brick means a slower arm, never a brownout. Plain PC USB stays logic-only: 5 V sits below the TMC5130's ~6 V undervoltage lockout.

Bus topology FIG.3

One CAN-FD bus, one elected coordinator

Nodes daisy-chain over Micro-Fit — a linear bus with power passing through, 120 Ω terminator plugs in the two unused end jacks. Every node is identical; one is elected coordinator and streams setpoints to the rest.

Programming model

Programs live on the arm

Fanuc/KUKA model, no PC tether: stored routines execute on the elected coordinator. The three stages below are the pipeline every move goes through.

1 Store

Motion programs live in the coordinator's flash — the G491's 512 K holds routines with no external memory.

uploaded over any transport

2 Plan

The coordinator runs inverse kinematics, blending, and S-curve interpolation on its M4F.

170 MHz · FPU · CORDIC

3 Stream

Interpolated setpoints and sync frames go out over CAN-FD; joints track them via TMC ramp targets.

1 kHz · 64-byte frames

Control transports

One command set, three ways in

USB

CDC virtual serial for control and config; ROM DFU for field flashing; esptool passthrough reflashes the C6; SWD for development.

bench / development

CAN-FD

The control path inside the arm — the coordinator streams setpoints and sync over the bus.

in the machine

WiFi / BLE

Via the C6 — provisioning, wireless control, and OTA updates for both chips.

remote

Every node is a gateway. USB↔CAN bridges inside the STM32; wireless↔CAN crosses the UART link in the C6. Plug into any single joint — by cable or by air — and you reach the whole chain. No external dongle.

Ecosystem tiers

One platform, two power tiers

Same G491 + C6 brain, same CAN-FD protocol, same firmware, same 5 V transceiver — only the power path changes with the motor.
